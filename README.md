# Аренда велосипедов

Java-проект для ЛР № 5 по статическому анализу и журналированию, вариант 8.
Сервис создаёт и закрывает аренду, запрещает выдавать занятый велосипед
или велосипед на обслуживании.

## Реализация

- `checkstyle.xml` задаёт правила для основных исходников и тестов:
  именование, отступы, длина строк до 120 символов, импорты, скобки
  и запрет `System.out` / `System.err`.
- `pom.xml` подключает Checkstyle, SLF4J и Logback. Проверка также
  привязана к фазе `verify`.
- `RentalService` пишет INFO при запросе и успешной аренде, WARN при
  отказе по состоянию велосипеда и ERROR с исключением при сбое сохранения.
  При сбое сохранения статус велосипеда не меняется, исключение передаётся вызывающему коду.
- `src/main/resources/logback.xml` направляет журнал в консоль и
  `logs/bike-rental.log`. Каталог журналов исключён из Git.
- `RentalServiceTest` содержит пять сценариев; для успешной аренды,
  повторной аренды и сбоя сохранения проверяются также уровни и сообщения журнала.

## Команды для защиты

Требуется JDK 21 и Maven с доступом к зависимостям проекта.
Команды ниже приведены для ручного запуска; Jenkins выполняет свои команды
автоматически после получения изменения из Git.

```bash
# Статический анализ без компиляции и запуска приложения
mvn checkstyle:check

# Тесты с демонстрацией INFO, WARN и ERROR
mvn test

# Приложение с успешной арендой и отказами WARN
mvn compile exec:java

# Полная проверка и упаковка
mvn verify
```

Сценарий ERROR воспроизводится в тесте
`doesNotChangeBicycleStatusWhenRentalCannotBeSaved`: тестовое хранилище
выбрасывает исключение при сохранении. В обычном приложении хранилище
работает в памяти, поэтому этот сбой специально в нём не создаётся.

## Jenkins

На этом компьютере Jenkins доступен по адресу <http://127.0.0.1:8080/>.
Задача: <http://127.0.0.1:8080/job/Lab3-BikeRental/>.
Она читает `Jenkinsfile` из ветки `main` репозитория
<https://github.com/ttyomaa6/bike-rental> и опрашивает Git каждую минуту.

Порядок этапов: Checkout → Build → Static Analysis → Test → Conditional → Package.
Этап Conditional сохранён из предыдущей лабораторной и по умолчанию пропускается.
Static Analysis вызывает `mvn checkstyle:check`; XML-отчёт сохраняется
в артефактах Jenkins даже при ошибке. При нарушении правил Maven возвращает
ненулевой код, поэтому последующие этапы не выполняются.

## Эксперимент с нарушением

1. Убедиться, что исходная версия проходит `mvn checkstyle:check`.
2. В `src/main/java/model/Bicycle.java` после `package model;` добавить
   `import java.util.List;`. Этот импорт не используется и не меняет бизнес-логику.
3. Повторить `mvn checkstyle:check`: ожидается нарушение `UnusedImports`
   и ненулевой код завершения.
4. Для демонстрации в Jenkins сохранить нарушение отдельным коммитом
   и отправить в `main`. Дождаться автоматической сборки.
5. В Console Output зафиксировать хеш коммита, ошибку `UnusedImports`
   на этапе Static Analysis, пропуск Test и Package, итог FAILURE.
6. Удалить импорт, выполнить повторный анализ, сохранить исправление
   отдельным коммитом и отправить в `main`.
7. Дождаться следующей автоматической сборки и зафиксировать SUCCESS,
   ноль нарушений и результаты тестов с сообщениями INFO/WARN/ERROR.

Для защиты нужны результаты двух реальных сборок Jenkins. Успешный
локальный анализ сам по себе не подтверждает выполнение Pipeline.
